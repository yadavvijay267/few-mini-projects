# Architecture

## Data

`assets/sensor_data.csv` — 2,000 rows, one per machine-day: `machine_id`,
`vibration` (mm/s), `temperature` (C), `runtime_hours`, `load` (0-1),
`cycles_since_service`, and the label `failed_within_30d` (0/1). The label
was generated by a documented model: failure probability rises with
vibration, temperature, runtime and time since service, plus noise — so the
model learns a real, recoverable signal rather than a memorised rule.

## Model

`RandomForestClassifier(n_estimators=200, random_state=42)` on the five
sensor features, stratified 80/20 split. Metrics reported: accuracy,
precision, recall, F1, ROC-AUC and the confusion matrix.

## RUL estimate

A simple, documented heuristic on top of the classifier: a health score
`h = 1 - P(failure)` is mapped to remaining useful life in days,
`RUL = round(h * 180)` capped at 180 days, with a per-machine degradation
trend from its recent history in the dashboard. It is labelled as an
estimate, not a measurement.

## Production path (NASA C-MAPSS)

Download the NASA C-MAPSS turbofan dataset (free, NASA Prognostics Data
Repository), map its 21 sensor columns + operating settings to the same
feature names, and re-run `src/train.py --data <cmapss.csv>`. The same
metrics, feature-importance chart and alert list are produced. In
production, add: per-machine time-series features (rolling means, trends),
a proper RUL regression model, and alert thresholds tuned with the
operations team (recall on failures matters more than precision).
